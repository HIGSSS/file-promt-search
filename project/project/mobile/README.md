# Mobile — Flutter клиент

Android-приложение для семантического поиска файлов через backend.

## Как это работает сейчас

1. Пользователь выдаёт приложению Android-разрешение **Доступ ко всем файлам**.
2. Приложение сканирует общее хранилище Android (`/storage/emulated/0`) и находит
   поддерживаемые документы и медиафайлы.
3. Приложение загружает найденные файлы на backend через `/upload-index`.
4. Backend сохраняет копии в `backend/storage/uploads/current/` и индексирует их.
5. Поиск выполняется через `/search`.
6. При открытии результата приложение скачивает backend-копию через `/download`
   во временную папку телефона и открывает локальный файл.

Такой сценарий нужен потому, что backend на ПК не может напрямую открыть путь
Android вида `/storage/emulated/0/...`.

Ручной выбор файлов через системный picker оставлен как запасной сценарий,
если пользователь не хочет выдавать приложению полный доступ к файлам.

Важно: `MANAGE_EXTERNAL_STORAGE` — чувствительное Android-разрешение. Для
дипломной демонстрации и локальной установки APK оно подходит, но при публикации
в Google Play потребуется обосновать, что поиск и управление файлами являются
основной функцией приложения.

## Запуск

```bash
flutter pub get
flutter run
```

Если Android-обвязка была удалена из архива, восстановите её из папки `mobile`:

```bash
flutter create --platforms=android .
```

После этого проверьте, что в `AndroidManifest.xml` остались:

- `android.permission.INTERNET`
- `android.permission.MANAGE_EXTERNAL_STORAGE`
- `android:usesCleartextTraffic="true"` для локального HTTP backend'а
- `FileProvider` для `open_filex`

Если Android-обвязка была восстановлена через `flutter create`, проверьте,
что нативный `MainActivity` содержит MethodChannel
`intelligent_file_search/storage` для открытия системного экрана
**Доступ ко всем файлам**.

## URL backend'а

- Android-эмулятор: `http://10.0.2.2:8000`
- Физический телефон через USB:

```bash
adb reverse tcp:8000 tcp:8000
```

и в приложении указать `http://localhost:8000`.

- Телефон и ПК в одной Wi-Fi сети: `http://<IP_ПК>:8000`.

## Демонстрация работоспособности на телефоне или эмуляторе

Для демонстрации нужен запущенный backend на ПК и Android-устройство
с заранее загруженными тестовыми файлами. Приложение сканирует общее
хранилище Android автоматически после выдачи разрешения **Доступ ко всем
файлам**.

### 1. Подготовить тестовые файлы

Создайте на ПК папку, например `demo_files`, и положите туда разные типы файлов:

- изображения: `.jpg`, `.png`, `.webp`;
- видео: `.mp4`;
- документы: `.pdf`, `.docx`, `.txt`, `.csv`, `.xlsx`.

Лучше брать файлы с понятным содержимым, чтобы затем легко проверить поиск:

- фото кота, машины, документа, человека;
- PDF/DOCX/TXT с фразами вроде `договор аренды`, `отчёт по продажам`,
  `резюме разработчика`;
- таблицу CSV/XLSX с несколькими строками и осмысленными заголовками.

### 2. Загрузить файлы на Android-эмулятор

Запустите эмулятор из Android Studio Device Manager, затем из терминала на ПК:

```bash
adb devices
adb shell mkdir -p /sdcard/Download/search-demo
adb push demo_files/. /sdcard/Download/search-demo/
```

В настройках приложения для эмулятора оставьте URL backend'а:

```text
http://10.0.2.2:8000
```

### 3. Загрузить файлы на физический телефон

Вариант через USB и ADB:

```bash
adb devices
adb shell mkdir -p /sdcard/Download/search-demo
adb push demo_files/. /sdcard/Download/search-demo/
adb reverse tcp:8000 tcp:8000
```

В приложении укажите URL:

```text
http://localhost:8000
```

Если телефон и ПК находятся в одной Wi-Fi сети, можно не использовать
`adb reverse`, а указать:

```text
http://<IP_ПК>:8000
```

Например: `http://192.168.1.10:8000`.

### 4. Провести демонстрацию

1. Запустите backend:

   ```bash
   cd backend
   ./run_server.sh
   ```

   На Windows можно использовать:

   ```powershell
   cd backend
   .\run_server.ps1
   ```

2. Запустите мобильное приложение:

   ```bash
   cd mobile
   flutter pub get
   flutter run
   ```

3. Откройте приложение на телефоне или эмуляторе.
4. Нажмите **Просканировать устройство**.
5. Если Android попросит разрешение, откройте настройки и включите
   **Разрешить доступ ко всем файлам** для приложения.
6. Вернитесь в приложение и снова нажмите **Просканировать устройство**.
7. Подтвердите загрузку найденных файлов на backend.
8. Дождитесь завершения индексации на экране статуса.
9. Вернитесь на главный экран и выполните несколько поисковых запросов:

   - `кот у окна` для проверки поиска по изображениям;
   - `договор аренды` для проверки PDF/DOCX/TXT;
   - `продажи` или `таблица клиентов` для проверки CSV/XLSX;
   - `видео` или описание сцены для проверки `.mp4`.

10. Откройте найденный результат. Приложение скачает backend-копию файла
   через `/download` и откроет её локально на Android.

### Что показать на защите

- на устройстве есть папка `Download/search-demo` с медиафайлами и документами;
- приложение успешно подключается к backend'у;
- приложение само находит поддерживаемые файлы в хранилище;
- найденные файлы загружаются и индексируются;
- поиск возвращает релевантные результаты по текстовым и медиа-запросам;
- найденный файл открывается прямо с телефона или эмулятора.
