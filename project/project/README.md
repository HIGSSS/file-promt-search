# Интеллектуальный поиск файлов

Дипломный проект: мобильное приложение семантического поиска файлов
на устройстве с применением машинного обучения.

## Структура

```
project/
├── backend/          # FastAPI + PyTorch + FAISS
├── mobile/           # Flutter Android-клиент
└── experiment/       # Датасет и runner для Precision@5
```

## Компоненты

| Часть       | Стек                                                     |
|-------------|-----------------------------------------------------------|
| Backend     | Python 3.10+, FastAPI, SigLIP, SBERT, EasyOCR, FAISS     |
| Mobile      | Flutter 3.19+, Dart                                       |
| Эксперимент | Python + requests, Flickr8k (реальные фото с подписями)  |

## Быстрый старт

Подробные инструкции — в README каждой подпапки.

```powershell
# 1. Запустить backend (Windows)
cd backend
.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000

# 2. Запустить mobile-приложение (в другом терминале)
cd mobile && flutter pub get && flutter run

# 3. Провести эксперимент на реальных фото
cd experiment
python3 build_real_dataset.py --out ./real_dataset --n 80
# проиндексировать: POST /index {"path": "<абс. путь к real_dataset>"}
python3 run_experiment.py --server http://localhost:8000 ^
    --dataset ./real_dataset --queries ./real_queries.json
```

## Изменения и улучшения

### Backend

1. **EasyOCR вместо PaddleOCR** — PaddleOCR конфликтовал с PyTorch через
   общий oneDNN-контекст и тянул отдельный тяжёлый фреймворк PaddlePaddle.
   EasyOCR работает поверх того же PyTorch, что SigLIP и SBERT — зависимости
   не конфликтуют, установка проще.

2. **OCR встроенных изображений в PDF** — раньше OCR применялся только
   к страницам без текстового слоя (сканам). Теперь для текстовых страниц
   дополнительно распознаются вставленные в них фото и скриншоты, чтобы
   текст на них попадал в индекс. Лимиты: не более 20 изображений на документ,
   иконки и декоративная графика < 80 px пропускаются.

3. **Исправлена индексация видео** — при forward-проходе SigLIP кадры не
   переносились на устройство модели (CPU/CUDA), из-за чего видеофайлы
   молча выпадали из результатов поиска. Добавлен явный `.to(DEVICE)`.

4. **Уточнены категории фильтрации** — «Документы» теперь строго `pdf`/`docx`;
   «Прочее» включает `txt`, таблицы (`csv`, `xlsx`), `pptx`, разметку и т.д.

5. **Поддержка GPU** — torch автоматически использует CUDA при наличии;
   на CPU-машинах работает без изменения зависимостей.

6. **Ленивая загрузка переводчика** — модель Helsinki-NLP/opus-mt-ru-en
   загружается не при старте, а только при первом медиа-поиске с русским
   запросом. Старт сервера стал заметно быстрее.

7. **Два отдельных FAISS-индекса** (media 768D + text 384D) — векторы разной
   размерности невозможно смешать в одном `IndexFlatIP`.

8. **Атомарная запись индексов** через `.tmp` + `os.replace` — защита от гонки
   между фоновой индексацией и одновременным запросом `/search`.

9. **Thread-safe `index_state`** с `threading.Lock` и `try_start()` — защита
   от повторного запуска параллельной индексации.

10. **Порог «осмысленного текста» для PDF** — определяется не только длиной,
    но и числом слов длиннее 2 символов: колонтитул «стр. 5 из 42» больше
    не считается полноценной текстовой страницей.

### Mobile

11. **Автообнаружение сервера в Wi-Fi** (`ServerDiscoveryService`) — приложение
    параллельно опрашивает все 254 адреса подсети /24 и автоматически находит
    backend. Раньше пользователь должен был вручную узнавать IP компьютера
    (ipconfig/ifconfig) и вводить его в настройках вручную.

12. **Исправлено зависание экрана настроек** — при неожиданном исключении
    в момент загрузки статуса сервера экран Settings зависал в состоянии
    спиннера навсегда. Загрузка обёрнута в `try/finally`, снятие спиннера
    гарантировано.

### Эксперимент

13. **Реальный датасет на основе Flickr8k** — добавлен скрипт
    `build_real_dataset.py`: скачивает реальные фотографии с человеческими
    подписями через API HuggingFace без тяжёлой библиотеки `datasets`.
    Подписи становятся поисковыми запросами с готовым ground truth.
    Результат на 80 фото: семантический поиск находит нужный снимок
    в топ-5 в **90% случаев**; подстрочный поиск по именам файлов — **0%**.

## Известные ограничения

- Сервер работает на ПК — ML-модели не помещаются в RAM мобильного устройства
- Индексация на CPU: ~1–5 сек на файл
- iOS не поддерживается
- Зашифрованные PDF пропускаются
- `.doc` (старый бинарный Word) не поддерживается, только `.docx`
- Индекс типа Flat: точный поиск, но линейный по числу векторов;
  для 100k+ файлов стоит перейти на HNSW или IVF
